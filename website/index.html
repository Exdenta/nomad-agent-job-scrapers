Open data contracts

Keep the source record intact

LinkedIn, EURAXESS, and YC jobs share exactly six top-level keys. Table destinations use a documented flat projection; candidate evaluations use a separate fit-scoring contract.

Inspect schemas and semantics →
nomad-agent-job-v1canonical
{
  "schemaVersion": "nomad-agent-job-v1",
  "identity": { "source": "linkedin", "externalId": "…" },
  "data": { "title": "…", "company": { "name": "…" } },
  "custom": null,
  "llm": { "status": "not_requested" },
  "raw": null
}

null means unknown or unavailable. [] means the source established that the field is empty. Neither is filler text.

Proof before claims

A green run is only one layer

Use the receipt chain appropriate to the outcome instead of treating one successful status as end-to-end proof.

  1. 01
    Actor

    Require terminal status, exit code, and the intended immutable build.

  2. 02
    Contract

    Validate the Actor-specific RUN-SUMMARY and every fetched dataset row.

  3. 03
    Reconciliation

    Match summary counts, dataset rows, and any declared usage charges.

  4. 04
    Destination

    Verify the named row, message, or record separately before calling delivery live.
