Destination contract

Airtable is the destination layer, not the Actor runner. Feed it only after the upstream integration has verified terminal status, exact build, summary, and dataset. Upsert on jobKey so repeated runs update the same source listing rather than duplicating it.

  • Use the provided field definition and import workbook to create the table.
  • Keep source, externalId, url, and jobKey as identity fields.
  • Do not manufacture empty strings where the canonical source says unknown.

Canonical versus flat

The flat row is convenient for filters, views, and assignments. It cannot represent every nested requirement, contact, source detail, or provenance edge. Store or retain a pointer to the canonical record whenever those fields affect decisions.

Delivery proof

An imported base or successful upstream run is not an Airtable delivery receipt. Verify a bounded smoke record in the named base and table, then confirm a repeated upsert does not create a duplicate.

Best for

Editorial review, lightweight operations, status tracking, and team-owned job pipelines.
