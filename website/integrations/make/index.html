How the scenario is bounded

The Apify Task owns the complete Actor input, item limit, charge cap, and exact build. The blueprint reads the completed run, rejects unsupported terminal states or wrong builds, validates the v4 summary, and only then projects dataset items.

  • LinkedIn Task: exact build 1.0.2.
  • EURAXESS Task: exact build 1.0.16.
  • At most one retry for the specific valid partial outcome defined by the shared retry contract.

Activation checklist

  1. Create the source-specific Apify Task with conservative caps.
  2. Import the matching Make blueprint.
  3. Set the Task ID, exact build, and spreadsheet identifiers.
  4. Attach Apify and Google credentials in Make.
  5. Run once and reconcile the run, dataset, and written rows before scheduling.

Keep canonical evidence

The Sheets row is a 32-field projection for operations. Preserve the canonical dataset whenever source-specific requirements, contacts, academic fields, or provenance matter.
