Reliable run sequence

  1. POST the complete Actor input with build=1.0.2 for LinkedIn or build=1.0.16 for EURAXESS.
  2. Set conservative item and total-charge limits.
  3. Poll the run or accept a webhook, then re-read authoritative run state.
  4. Reject failed, aborted, timed-out, or wrong-build outcomes.
  5. Validate the v4 summary and paginate the entire default dataset.

Consumer contract

Keep the nested nomad-agent-job-v1 record as the source of truth. Use jobKey for idempotency, retain unknown values as null, and treat an established empty list differently from unavailable data.

Webhook payloads are notifications, not the authoritative dataset. Re-read the run and storage objects before applying business logic.

Operational boundary

An HTTP 2xx response proves request acceptance at that layer. It does not prove terminal Actor success, complete retrieval, a valid record set, or delivery into your database.

Best for

Job boards, internal applications, databases, custom alert services, and programmatic research.
