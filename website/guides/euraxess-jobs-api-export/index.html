EURAXESS jobs API and export options

Searching public research opportunities, publishing your institution’s vacancies, and exporting records into an internal system are separate workflows. Start with the direction of data, then choose the narrowest permitted integration.

Explore normalized EURAXESS jobsUse the REST pattern

Three jobs-data directions

  • Find opportunities as a researcher: use the official EURAXESS search and MyEURAXESS alert tools when they satisfy the task.
  • Publish vacancies as an institution: use the official posting workflow or any institution-approved publishing feed. That inbound publishing path does not imply a general read/search API.
  • Export public vacancies into software: evaluate a permitted independent scraper or licensed source, then retain evidence and source identity.

The official EURAXESS Jobs & Opportunities portal ↗ is the authoritative starting point for current search and publishing options.

Why a publisher feed is not a search API

A publisher integration sends an organization’s vacancies into EURAXESS. A read API would retrieve EURAXESS records for a consumer. Direction, authorization, schema, and allowed reuse differ. Credentials or technical documentation for the first do not grant access to the second.

Before building, write one sentence that states who owns the jobs, which direction they move, who will see them, and how long they will be retained. If that sentence describes publishing your institution’s own jobs, stay with the official publisher route.

What normalized extraction adds

The Nomad Agent EURAXESS Actor independently searches public vacancies and maps common data into nomad-agent-job-v1. It retains source-specific research fields—such as research domains, researcher profiles, programmes, funding, requirements, languages, deadlines, and named contacts when published—inside a versioned custom object.

This is useful for permitted internal tracking, research-job alerts, and data pipelines that need stable identity and source evidence. It is not affiliated with or endorsed by EURAXESS or the European Commission, and it does not grant permission to crawl or republish.

Run a five-row export

The maintained examples pin integration-tested build 1.0.16; the Store default observed on 2026-09-03 was 1.0.20. Use the tested pin or revalidate the newer build explicitly.

  1. Confirm Actor availability and account access.
  2. Pin the intended build and set an explicit item and maximum charge cap.
  3. Choose one keyword, location, and supported calendar recency value: 24h, 7d, 30d, or any.
  4. Request at most five jobs; keep translation, AI enrichment, raw output, analytics, and cross-run deduplication disabled.
  5. Verify terminal success, exact build, v4 summary, full dataset count, six-root rows, and identity.source = euraxess.
  6. Retain the canonical JSON. Derive a flat destination row only if the next system cannot accept nested data.

Choose an export destination

  • JSON/API: best when an application needs the full canonical record and source-specific taxonomy.
  • n8n or Make: best for an inspectable scheduled workflow and duplicate-safe Google Sheets upsert.
  • Airtable or CSV: useful for common operational fields, with explicit loss of nested academic detail.
  • MCP: useful for bounded interactive searches where an agent can keep canonical results available.

Use jobKey = source:externalId for source-record idempotency. A title or institution name is not a safe key.

Evidence and privacy checklist

  • Preserve null as unknown and [] as explicitly empty.
  • Keep static extraction, description-derived facts, normalization, translation, optional LLM output, and raw text distinguishable.
  • Review source terms, licensing, privacy obligations, and applicable law before retention or republication.
  • Minimize named-contact and description storage; apply destination access and deletion policies.
  • Do not advertise an official API, partnership, accuracy rate, or destination delivery without direct evidence.

Recommended default

Use official EURAXESS search and alerts for a human job search. Use the official publishing route for vacancies your organization owns. Use independent normalized extraction only when a software workflow genuinely needs it and the intended access, retention, and reuse have been reviewed.
